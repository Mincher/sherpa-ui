Composition Validator Demo

This demo shows the Sherpa UI composition validator in action. The validator enforces tier hierarchy rules and data-accepts constraints to prevent invalid component nesting.

Tier Hierarchy Violations

Components are organized into 5 tiers (1=shell/nav, 2=container/overlay, 3=content, 4=control/input/display, 5=utility). A tier-N component can only host children whose tier is N or deeper (tier number ≥ N).

❌ Invalid: Button (tier 4) containing Container (tier 2) This should be rejected
<sherpa-button>
  <sherpa-container>...</sherpa-container>
</sherpa-button>

Check console for validation warning.

✅ Valid: Container (tier 2) containing Button (tier 4) This is allowed
<sherpa-container>
  <sherpa-button>...</sherpa-button>
</sherpa-container>

Role Constraints (data-accepts)

Slots can restrict what roles they accept via the data-accepts attribute. This provides fine-grained control over composition.

❌ Invalid: Metric (display role) in control-only slot Should be rejected
<sherpa-toolbar>
  <sherpa-metric slot="actions">...</sherpa-metric>
</sherpa-toolbar>

<!-- Toolbar template: -->
<slot name="actions" data-accepts="control"></slot>

Check console for validation warning.

✅ Valid: Button (control role) in control-accepting slot Add
<sherpa-toolbar>
  <sherpa-button slot="actions">...</sherpa-button>
</sherpa-toolbar>

Non-Sherpa Elements

By default, slots with data-accepts reject non-Sherpa elements. Add html to the accepts list to allow free-form HTML.

❌ Invalid: Non-Sherpa element without html in accepts
Plain HTML div - should be rejected
<sherpa-container>
  <div slot="header">...</div>
</sherpa-container>

<!-- Container template: -->
<slot name="header" data-accepts="content"></slot>

Check console for validation warning.

✅ Valid: Sherpa component in the slot Sherpa component - allowed
<sherpa-container>
  <sherpa-section-header slot="header">...</sherpa-section-header>
</sherpa-container>

Strict Mode

When strict mode is enabled, rejected elements are flagged with data-slot-rejected="true" and hidden via CSS. Without strict mode, violations are only logged to the console (warn-only mode).
