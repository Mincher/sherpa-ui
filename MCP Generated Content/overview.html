MCP

Pages in this section were composed end-to-end by querying the Model Context Protocol server that ships with Sherpa UI. The MCP server exposes query_component, compose_view, get_pattern, search_api, and 19 other tools over stdio — every page below is the result of asking it “build me a dashboard for X” and reading back the recommended component APIs, slot composition, and data shapes.

  1. Spawned node mcp-server/index.js over stdio and completed the JSON-RPC initialize handshake.
  2. Used get_architecture + list_components to discover the role taxonomy and which components are available.
  3. For each scenario, called compose_view with a layout pattern (e.g. dashboard-grid) and a list of components the page should use.
  4. Called query_component on every relevant tag to confirm attribute names, accepted values, and setData() payload shapes from the actual schema.
  5. Pasted the generated markup into an HTML partial, then wrote a small .setup.js sibling module to feed real data via the component APIs the MCP server documented.

Each card opens a fully working example page. The markup is real Sherpa UI — the data layer is supplied by the .setup.js companion file the MCP server recommended.
